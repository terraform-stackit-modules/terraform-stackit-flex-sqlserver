# Terraform STACKIT SQLServer Flex module

Terraform module which provisions a [STACKIT SQLServer](https://registry.terraform.io/providers/stackitcloud/stackit/latest/docs/resources/sqlserverflex_instance) Flex instance, its databases and its users on [STACKIT](https://www.stackit.de/en/).

This repository is not from the official STACKIT organization.

> **Naming.** The repository is `terraform-stackit-flex-sqlserver` (readability), while the provider
> resources are `stackit_sqlserverflex_instance` / `stackit_sqlserverflex_database` /
> `stackit_sqlserverflex_user`.

## Usage

```hcl
module "flex_sqlserver" {
  source  = "terraform-stackit-modules/flex-sqlserver/stackit"
  version = ">= 1.0.0"

  project_id        = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  name              = "app-sqlserver"
  sqlserver_version = "2022"
  flavor_id         = "4.16-Single"
  backup_schedule   = "0 0 * * *"
  retention_days    = 30

  storage = { class = "premium-perf2-stackit", size = 5 }
  network = { acl = ["0.0.0.0/0"] }

  users = {
    app = {
      username = "app_user"
      roles    = ["##STACKIT_DatabaseManager##"]
    }
  }

  databases = {
    app = {
      name  = "app_db"
      owner = "app_user"
    }
  }
}
```

## Composite module

- `modules/instance` — the `stackit_sqlserverflex_instance` (toggled by `create_instance`).
- `modules/database` — `stackit_sqlserverflex_database` entries (`for_each` over `databases`).
- `modules/user` — `stackit_sqlserverflex_user` entries (`for_each` over `users`).

The root wires them together and, when `create_instance = false`, targets an existing instance via
`instance_id`. Databases are created **after** users (`depends_on`) so a database `owner` exists.

## Examples

- [`basic`](./examples/basic) — minimal instance + one user + one database.
- [`complete`](./examples/complete) — prod-like: restricted ACL, longer retention, a database with
  explicit collation/compatibility, multiple users. Mirrors `complete-mssql` in terraform-aws-rds.
- [`replica`](./examples/replica) — high availability. NOTE: STACKIT SQLServer replication is
  carried by the **flavor** (pick a replicated flavor); there is no RDS-style `replicate_source_db`.

## Notes

- Generated user passwords are exposed via the **sensitive** `user_passwords` output.
- `users` / `databases` are maps keyed by a **stable identifier**; the instance\_id (known after
  apply) is only a resource attribute, never a `for_each` key.
- A database's `owner` must be an existing user — the module orders databases after users via
  `depends_on = [module.user]` (the owner is a plain string, so Terraform has no implicit
  dependency, and the STACKIT API returns 404 "owner not found" if the DB is created first).
- `retention_days` must be between 30 and 90.

## Terratest

The `test/` directory holds Terratest integration tests that apply the example root modules against a real STACKIT project (requires `STACKIT_SERVICE_ACCOUNT_KEY` and `STACKIT_PROJECT_ID`). Only the `basic` example runs in CI; `complete`/`replica` self-skip unless `TERRATEST_RUN_ALL` is set.

```bash
cd test
go mod init github.com/terraform-stackit-modules/terraform-stackit-flex-sqlserver
go get github.com/gruntwork-io/terratest@v1.0.1
go mod tidy
TERRATEST_RUN_ALL=1 go test -v -timeout 90m ./...
```
